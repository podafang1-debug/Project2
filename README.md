# 启智训练台

项目采用浏览器游戏前端 + Python 本地服务 + SQLite 数据库的分层结构。推荐通过 Python 服务启动，此时 SQLite 是账号、儿童档案、授权关系、训练记录、评估、画像、风险和专业方案的主数据源；直接打开网页只保留无后端的静态演示能力。

系统采用三个登录角色：儿童、家长、康复专业人员。家长注册后会自动建立对应儿童档案，同一个手机号和密码可从“儿童”入口进入闯关训练，也可从“家长”入口查看分析与答题情况；原管理能力已合并到康复专业人员工作台。

## 推荐启动方式

电脑安装 Python 3.10 或更高版本后，在项目目录运行：

```powershell
python backend/server.py
```

登录页提供家长注册和康复专业人员注册。家长注册后立即可用并自动建立儿童账号；首次康复专业人员注册需要输入启动窗口显示的一次性安全初始化码，之后的专业账号进入待审核状态，由已启用的康复专业人员在“账号与授权”中启用。系统默认不再自动生成示例账号。

手机号是 `app_users.phone` 的数据库主键，也是会话和儿童授权关系使用的账号标识。密码通过随机盐和 PBKDF2-SHA256 保存，明文不会写入数据库或浏览器存储。登录成功后服务端签发 12 小时会话；所有儿童数据接口都会同时校验数据库角色权限和 `user_child_bindings` 授权关系，客户端自报角色不作为权限依据。连续 5 次登录失败会将该客户端对相应手机号的尝试锁定 15 分钟。
打开终端打印出的本地网址（默认 `http://127.0.0.1:8876`；被占用时会自动寻找 8877-8885）。服务首次启动会自动建立 `backend/training_platform.db`。Windows 用户也可以直接双击项目根目录的 `启动平台.bat`。

## 生成 Windows 便携版

双击项目根目录的 `打包便携版.bat`。打包程序会自行准备隔离 Python、OCR、CrewAI、Ollama 和 `qwen3:0.6b`，并输出到 `release/`；不会复制当前数据库、账号、儿童档案、文档密钥、备份或 Git 历史。详细参数见 `打包说明.md`。该脚本只负责构建，不会启动最终程序进行冒烟测试。

专业侧不再拆分“医师”“治疗师”和“管理员”账号。康复专业人员在同一实名会话内完成患者选择、专业评估、训练计划复核、风险暂停/解除、方案签署、内容审核与机构治理。

## 历史扫描档案批量导入

先安装本地离线识别组件：

```powershell
python -m pip install -r backend/requirements-ocr.txt
```

少量 PDF：登录“康复专业人员”，进入“设置 → 历史扫描档案导入”。上传后依次完成离线 OCR、候选字段复核、关联儿童、六维分数专业确认和正式入档。

200 份以上材料建议放入独立文件夹，再运行：

```powershell
python backend/bulk_import.py "E:\待导入档案" --recursive
```

原始 PDF 和 OCR 全文使用本机密钥加密，目录与密钥均被 Git 忽略。自动识别结果只作为候选值，专业人员复核前不会进入正式档案。六维能力分数必须由专业人员依据合法评估填写，程序不会从叙述文本猜测临床分数。

### 档案画像与个性化训练 Agent

扫描识别完成后，专业端可以点击“从文字生成画像与题目”。Agent 会把文字拆成优势、支持需求、提示依赖和风险证据，按注意与感知、记忆、执行与逻辑、语言沟通、社会情绪、生活适应生成 L0-L4 训练起点，并保留文件页码和置信度。

Agent 同时为 22 个训练模块生成起始难度、选项数量、指令步数、提示方式、训练频率、时长和可直接作答的 Emoji 游戏题。自动结果先保存为草稿；康复专业人员可以逐域调整等级，签署后才会成为当前画像和儿童端有效题目。档案出现癫痫、自伤、攻击、严重情绪爆发、吞咽或跌倒风险时，题目只允许预览，线上训练保持暂停。

纯文字画像属于训练起点建议，不替代标准化量表或医学诊断。资料不足的领域保持 L0，并通过低刺激探索题收集真实表现，不使用虚构的精确分数。

### 儿童端 20 关课程 Agent

儿童端训练地图由 backend/level_agent.py 编排为 20 个渐进关卡，每关 5 个不同形式的小任务。课程优先参考初测六域训练起点、档案中的语言与生活支持信息和近期独立完成率；关卡展示顺序不改变专业人员审核后的题目内容。儿童可在地图上选择“不想玩哪些”，被排除的游戏类型会由同难度的其他活动替换。

AI Agent 默认启用，模型为本地 `qwen3:0.6b`。CrewAI 通过自定义 `BaseLLM` 直接连接本机 Ollama，不使用 LiteLLM 或云端代理；只处理年龄段、六域分数、支持级别、近期领域正确率和排除项，不发送姓名、儿童编号、诊断或档案原文。模型不可用或输出不合规时自动回退到本地规则。

## 免费本地 AI

源码运行时需先安装 Ollama 并下载轻量模型；便携版已经集成，无需接收方另行安装：

```powershell
ollama pull qwen3:0.6b
```

保持 Ollama 运行，平台会通过 Python 后端调用它生成儿童友好画像文案。只传递匿名六域汇总分数，不传姓名、诊断或逐题答案。Ollama 不可用时，平台会自动使用安全离线文案，不影响画像分数计算和保存。

## 数据位置

- SQLite 主副本：`backend/training_platform.db`
- 浏览器兼容副本：当前浏览器的 localStorage
- 身份与权限表：`roles`、`permissions`、`role_permissions`、`app_users`、`auth_sessions`、`auth_login_failures`、`user_child_bindings`
- 业务表：`children`、`training_records`、`safety_flags`、`ability_profiles`、`ai_inferences`、`assessments`、`intervention_logs`、`care_records`

## 专业服务闭环

康复专业人员可从“设置 → 专业服务闭环”依次完成接案与禁忌档案、分层 IEP/ITP 目标、AI 方案编辑签署、周期复评、结案与随访。家长只能查看并确认共同目标，不能编辑或签署专业方案。所有新版本均单独留存，签署后的历史版本不会被覆盖。

后端会再次检查角色权限，因此不能通过手工调用接口绕过前端菜单限制。正式量表只允许录入合法施测结果，程序不内置受版权保护的题目、常模或评分表。

## 专业服务与治理闭环

治理功能必须通过 Python 本地服务使用，静态页面不会提供离线账号或伪造保存成功。内容按“草稿 → 审核 → 发布”流转，驳回必须填写原因；历史版本可追溯并可回滚为新版本。机构、班级、账号状态、密码重置、会话撤销及账号与儿童的授权绑定均由服务端保存。

康复专业人员可在“我的患者”中自行勾选需要跟进的家庭儿童账号，保存后其档案、训练与分析页面只加载已选择的患者。内容发布、账号管理、授权共享、请求处理和备份操作都要求重新输入当前康复专业人员登录密码。

家长的知情同意与数据请求会进入专业端治理队列。康复专业人员可以记录受理、处理、完成或驳回状态与说明，但系统不会仅凭一次网页点击自动执行不可恢复的数据删除。机构共享必须明确范围和有效期，并可随时撤销。

服务器备份保存在 `backend/backups/`，该目录不会提交到 Git。专业端可以创建 SQLite 一致性备份并运行完整性校验；恢复操作应在停服、核对备份来源并保留现有数据库副本后，由受控运维流程执行。
