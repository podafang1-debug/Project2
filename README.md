# 启智训练台

项目采用浏览器游戏前端 + Python 本地服务 + SQLite 数据库的分层结构。直接打开网页仍可演示；通过 Python 服务启动后，儿童画像和专业评估会额外持久保存到 SQLite。

系统采用四个复合角色：儿童、家长、康复医疗专业人员、内容与机构管理员。医疗评估和康复训练职责归入同一专业角色；内容审核与组织治理归入复合管理员，但管理员仍只能查看脱敏运营汇总，不能读取儿童临床档案。

## 推荐启动方式

电脑安装 Python 3.10 或更高版本后，在项目目录运行：

```powershell
python backend/server.py
```

打开终端打印出的本地网址（默认 `http://127.0.0.1:8765`；被占用时会自动使用 8766-8774）。服务首次启动会自动建立 `backend/training_platform.db`。

## 历史扫描档案批量导入

先安装本地离线识别组件：

```powershell
python -m pip install -r backend/requirements-ocr.txt
```

少量 PDF：登录“康复医疗专业人员”，进入“设置 → 历史扫描档案导入”。上传后依次完成离线 OCR、候选字段复核、关联儿童、六维分数专业确认和正式入档。

200 份以上材料建议放入独立文件夹，再运行：

```powershell
python backend/bulk_import.py "E:\待导入档案" --recursive
```

原始 PDF 和 OCR 全文使用本机密钥加密，目录与密钥均被 Git 忽略。自动识别结果只作为候选值，专业人员复核前不会进入正式档案。六维能力分数必须由专业人员依据合法评估填写，程序不会从叙述文本猜测临床分数。

## 免费本地 AI（可选）

安装 Ollama 后下载轻量开源模型：

```powershell
ollama pull qwen3:0.6b
```

保持 Ollama 运行，平台会通过 Python 后端调用它生成儿童友好画像文案。只传递匿名六域汇总分数，不传姓名、诊断或逐题答案。Ollama 不可用时，平台会自动使用安全离线文案，不影响画像分数计算和保存。

## 数据位置

- SQLite 主副本：`backend/training_platform.db`
- 浏览器兼容副本：当前浏览器的 localStorage
- 表：`ability_profiles`、`ai_inferences`、`assessments`、`intervention_logs`、`care_records`

## 专业服务闭环

康复医疗专业人员可从“设置 → 专业服务闭环”依次完成接案与禁忌档案、分层 IEP/ITP 目标、AI 方案编辑签署、周期复评、结案与随访。家长只能查看并确认共同目标，不能编辑或签署专业方案。所有新版本均单独留存，签署后的历史版本不会被覆盖。

后端会再次检查角色权限，因此不能通过手工调用接口绕过前端菜单限制。正式量表只允许录入合法施测结果，程序不内置受版权保护的题目、常模或评分表。
